# 标记、确认和母版导出工具

`scripts/prepress.py` 依赖 Pillow。它提供可重复的标记与图层组合，不负责识别图像语义、精细分割或验证真实用户授权。没有当前用户确认时，不得自行运行确认步骤。

脚本原图入口只接受 RGB/RGBA，并检查已有 ICC 是否为 RGB。CMYK、灰阶或配置不匹配时先停止，不将旧 ICC 硬套到 RGB 像素。需要时用支持色彩管理的工具另存 RGB 工作副本，保留原文件与转换说明；再以工作副本建立方案、确认与同位蒙版。没有正确转换条件时可讨论设计，但不能声称已经完成可印刷的色彩转换。

## 1. 建立方案

为每次图片任务建立独立输出目录。原图使用真实文件路径；坐标是经 EXIF 方向规范化后原始像素坐标，不是屏幕截图坐标。标记前先在当前工具中观察图片，不能照抄例子的范围。

方案 JSON 示例（坐标仅说明格式）：

```json
{
  "elements": [
    {
      "id": "F01",
      "label": "顶部标题",
      "treatment": "foil",
      "reason": "用标题建立反光焦点，避开人物面部",
      "polygon": [[40, 30], [250, 30], [250, 90], [40, 90]]
    },
    {
      "id": "P01",
      "label": "人物脸部",
      "treatment": "protect",
      "reason": "保留白墨以稳定肤色",
      "polygon": [[90, 110], [170, 110], [170, 210], [90, 210]]
    }
  ]
}
```

多边形用于标记语义范围，允许是粗轮廓；最终精抠边界要另做蒙版，不从粗多边形自动生成。未编号区域默认不发闪。

```powershell
python "<skill目录>/scripts/prepress.py" annotate --source "<原图>" --plan "<方案.json>" --out "<任务目录>"
```

生成 `01_annotation.png`、`plan_review.md`、`plan_manifest.json`。打开并检查标记图，确实覆盖了正确元素后，用绝对路径图片标签展示它。输出同时包含左右图例，不只输出文字表。

**在这里等待确认。** 没有厂家模板仍可先完成标记。创建技能本身不意味着用户批准了未来某张图片的发闪元素。

## 2. 用户明确确认后记录

例如用户真实回复“同意 F01 发闪，P01 保持白墨”，才运行：

```powershell
python "<skill目录>/scripts/prepress.py" approve --out "<任务目录>" --ids F01 --evidence "同意 F01 发闪，P01 保持白墨"
```

`--evidence` 记录真实回复，不要编造。只有需要发闪的获批 ID 放进 `--ids`；用户说全部不闪时可用空的 `--ids`，输出全覆盖白墨母版。方案和原图哈希被绑定；改方案、换图后旧确认失效。脚本检查的是记录一致性，不能证明对话中的授权。

## 3. 精细分割

为每个获批 ID 制作独立灰度 PNG，例如 `masks/F01.png`：

- 尺寸、位置与规范化原图完全一致；不自动裁小。
- 图像模式 `L` 或 `1`，白色 255 表示该元素的发闪区域，黑色 0 表示其余区域。
- 边缘可有自然抗锯齿；不能把工具的黑白含义弄反。内部透明孔洞需要保留。
- 若分割工具返回 RGBA 选区，用它的正确 alpha 得到灰度蒙版；先检查白=被选区域，不能对整个 RGBA 直接转灰度而丢掉 alpha 语义。
- 不把标记副本、圈选笔迹、阴影、棋盘格或模型重绘的颜色用作原图。
- 脸、文字线稿等附近放大检查；手工路径适合清楚规则轮廓，复杂发丝或半透明物需足够可靠的工具和复核。

脚本只合并 `approved.json` 中的元素，不自动查找额外蒙版。精细蒙版是审批范围的边界细化；新增发闪元素或实质改变范围，应重新标记并确认。脚本无法判断一个同名蒙版在语义上是否正确，模型必须视觉复核。

```powershell
python "<skill目录>/scripts/prepress.py" export --out "<任务目录>" --mask-dir "<蒙版目录>"
```

脚本先检查所有输入，再创建 `delivery/`。缺确认、蒙版缺失、原图或方案变化、尺寸不匹配时拒绝输出。每次交付使用新的任务目录；已有 `delivery/` 不覆盖，修订时保存新版本避免残留旧元素。

## 4. 每版效果和定稿确认

导出后先做视觉检查，再展示给用户，明确询问：“这版提取出的炫彩部分是否满意？可以继续厂家适配，还是需要修改编号/边缘？”每次改版都要新目录与新版本号，不能默认上一版的批准涵盖新版效果。

用户明确认可当前效果版后记录：

```powershell
python "<skill目录>/scripts/prepress.py" review --out "<任务目录>" --stage proof --decision approve --evidence "<用户真实回复>"
```

不满意则记录 `--decision revise`，按反馈修订并重新展示。收到对最终交付版的明确认可，再用 `--stage final --decision approve` 记录定稿。工具将确认绑定到实际交付文件字节；文件变化后旧效果确认不能用于定稿，须展示变化后的效果并确认。适配厂家格式时，如内容改变应复核效果；只有版本或格式变化也需要按用户要求确认新的 C 版。

这两个命令只记录用户反馈并核对一致性；不能证明审美满意或厂家规格通过，也不会发送文件、下单或验证实际印刷能力。

## 5. 验证与交付

自动检查不能替代审美和轮廓检查。打开标记、白墨检查图、套位图和关键抠图，在原始尺寸确认：

1. 发闪位置与用户批准的编号一致；未获批区域和重要脸部没有误透底。
2. 彩色母版和原图可见像素相同；白墨 RGB 为白、透明度为覆盖量。
3. 所有印刷母版同画布、同方向、同位置，没有棋盘格被烘焙或边缘杂点。
4. 交付说明明确 `03_foil_mask_review.png` 的白形代表发闪，不代表印白墨。
5. 母版保留源图原有 ICC（若有），不虚构物理尺寸或分辨率；按厂家模板另做适配，未经核实不叫“可直接上机”。

脚本是源图像素忠实的组合器，没有自动分割模型、PSD 导出器、专色或 CMYK 印刷适配器。不要承诺这些能力已经具备。
